# 100人之后：让目录值得反复回来

当前目标是让访客很快看懂用途、选对一个方法、完成一次任务，再愿意收藏和反馈。人物扩展暂停。设计选择是编辑判断，不能保证星标增长。

## 已实现的入口

| 访客要判断什么 | 对应设计 | 理由 |
|---|---|---|
| 这是一个什么项目 | “给 AI 一座中国思想的工具箱”与100人品牌图 | 用熟悉的人物和实际用途解释集合 |
| 和我有什么关系 | 六类任务、12个精选方法 | 先从当前问题切入，减少逐个人名搜索 |
| 第一件事怎么做 | 一个安装命令与60秒试用任务 | 让阅读自然连接到可检查的成果 |
| 具体价值是什么 | 原创虚构目标产物与四个可复制任务 | 明确期待的输出，不冒称已经通过模型评测 |
| 为什么可以相信 | 来源、边界、CI与未运行评测状态 | 让读者区分结构验证和真实模型效果 |
| 以后怎样找回来 | 总目录回链、三个同类方法、收藏入口 | 在人物之间形成可理解的导航 |
| 用坏了怎样改进 | 可复现的任务反馈表单 | 把失败转成能修订的材料 |

中英文目录、全部人物链接和场景推荐来自 `catalog/skills.json`。完整100人名单与安装命令默认折叠。人物原正文保留；仅系列受管区块更新。GitHub About 使用具体任务介绍、统一Topics和总目录Website。

## 下一阶段的检查顺序

1. 优先在明确客户端和模型版本下运行精选方法的行为用例，保留输入、原始输出、评分和失败。
2. 收集愿意公开反馈的真实任务；用一次任务的交付证据判断方法是否有用。
3. 根据失败修订方法、资料和入口；把验证状态与新材料记录在提交中。
4. 再观察哪些任务被反复采用，调整唯一目录中的推荐排序。

这些是后续工作，不表示已经完成；未建立额外遥测或自动推广。星标数可作为公开反馈的一部分，不能替代实际任务质量。没有为实际星标增长作数值承诺。
